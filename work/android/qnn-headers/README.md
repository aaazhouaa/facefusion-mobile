# QNN headers (tracked subset)

The 27 headers under `QNN/` are the **complete include closure** the native build
needs to compile `ffqnn.cpp` against the Qualcomm QNN API. They are copied from the
QAIRT SDK staging tree (`app/src/main/cpp/include/QNN`, itself generated by
`stage_qnn.sh`) and checked into Git so a fresh clone can build the native library
without downloading the ~2 GB QAIRT SDK first.

## Source

- SDK: QAIRT 2.50.0.260828
- Staged: 2026-09-07T11:40:57Z (see `app/src/main/jniLibs/QNN_STAGED.txt`)
- Copied verbatim; verified byte-identical with `cmp`.

## What is here

| Root | Files |
|---|---|
| `QNN/` | 17 headers: Backend, Common, Context, Device, Error, GlobalConfig, Graph, Interface, Log, Mem, OpDef, OpPackage, Profile, Property, Signal, Tensor, Types |
| `QNN/HTP/` | 3: QnnHtpDevice, QnnHtpDeviceConfigShared, QnnHtpPerfInfrastructure |
| `QNN/System/` | 7: QnnSystemCommon, Context, Dlc, Interface, Log, Profile, Tensor |

The closure was derived by preprocessing `ffqnn.cpp`'s 13 direct includes with the
NDK clang and both include roots (`-I include -I include/QNN`), which is exactly how
CMake compiles it.

## Updating

When the SDK is upgraded, re-run `stage_qnn.sh` (which still copies the full SDK
`include/QNN` into the ignored `cpp/include/` tree), then re-copy the 27 files here
and commit. The `QNN_STAGED.txt` marker in `jniLibs/` records which SDK the staged
tree came from.
